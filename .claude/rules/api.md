# Правила для HTTP/gRPC слоя

## Валидация
- Все входящие данные валидировать до передачи в service-слой
- Для REST использовать структуры с тегами `validate:"required,min=1"`
- Возвращать 400 с описанием ошибки валидации, не 500

## Формат ошибок REST
```json
{
  "error": "описание ошибки",
  "code": "PAYMENT_NOT_FOUND"
}
```

## Логирование
- Логировать каждый входящий запрос через middleware, не внутри хендлеров
- В хендлере логировать только бизнес-ошибки уровня ERROR
- Не логировать тело запроса — могут быть чувствительные данные

## Авторизация
- Проверка прав только через middleware, не внутри хендлера
- Хендлер получает уже аутентифицированный контекст
